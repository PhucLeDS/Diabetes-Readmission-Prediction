# Weka model training

Java + Weka pipeline that trains, tunes and evaluates classifiers on the ARFF files written by
[02_split_export.ipynb](../../notebooks/02_split_export.ipynb). It follows the protocol in the
main README: choose settings on Train/Validation, refit on Train + Validation, score Test once.

```
load -> encode -> train -> tune -> evaluate
```

| Step | File | What it does |
|---|---|---|
| 1 load | `model/DataLoader.java` | Reads `train`, `validation`, `train_validation`, `test_for_train_validation` `.arff` from `data/weka/`; checks headers, row counts, positive label |
| 2 encode | `model/Encoder.java` | Logistic only: fill missing + one-hot, inside the model so it is fitted on training data only |
| 3 train | `model/Trainer.java` | Model list and settings to try; fits one setting (J48/RandomForest on class-balanced weights) |
| 4 tune | `benchmarking/Tuner.java` | Fits each setting on Train, keeps the best Validation PR-AUC, then the threshold with the best Validation F1 |
| 5 evaluate | `benchmarking/Benchmark.java` | Refits the chosen setting on Train + Validation, scores the holdout once at that threshold, writes the CSV |
| metrics | `benchmarking/Metrics.java` | Accuracy, ROC-AUC, PR-AUC, precision, recall, F1, Brier for the positive class |
| tests | `test/PipelineTest.java` | 15 unit tests on synthetic data covering every step and one full run |
| tests | `test/RealDataTest.java` | Checks the real `data/weka/` files are ready (skips if not generated) |

Models: Logistic, NaiveBayes, J48, RandomForest, LogitBoost.

## Requirements

- Java 16 or newer (`java -version`)
- Weka 3.9.x: only `weka.jar` from the installation folder is used
- The ARFF files in `data/weka/`, generated by the preparation notebooks (see the main README)

## Build, test, run (Git Bash, from the repository root)

Set `WEKA_JAR` to your installation, then:

```bash
WEKA_JAR="C:/Program Files/Weka-3-9-7/weka.jar"
SRC=weka_java/model_training
javac -cp "$WEKA_JAR" -d build $SRC/model/*.java $SRC/benchmarking/*.java $SRC/test/*.java

java --add-opens java.base/java.lang=ALL-UNNAMED -cp "$WEKA_JAR;build" PipelineTest
java --add-opens java.base/java.lang=ALL-UNNAMED -cp "$WEKA_JAR;build" RealDataTest
java -Xmx3g --add-opens java.base/java.lang=ALL-UNNAMED -cp "$WEKA_JAR;build" benchmarking.Benchmark
```

The classpath separator is `;` on Windows and `:` on macOS/Linux. `--add-opens` silences a
warning from Weka's package loader on Java 17+. A full run takes a few minutes.

`benchmarking.Benchmark` takes two optional arguments: the data folder (default `data/weka`) and
the positive label (default `readmitted`, from `config/target_mapping.json`). A folder with the same
four file names and another target, for example readmission within 30 days, runs unchanged:

```bash
java -Xmx3g --add-opens java.base/java.lang=ALL-UNNAMED -cp "$WEKA_JAR;build" benchmarking.Benchmark data/weka_lt30 readmitted_lt30
```

Output: `outputs/tables/model_training/<folder>_results.csv` (ignored by Git), one row per model:
the chosen setting and threshold, then accuracy, ROC, PR, precision, recall, F1 and Brier on
Validation (`val_*`, model fitted on Train) and on the holdout (`test_*`, model refitted on
Train + Validation).

## Reading the metrics

- **Accuracy, precision, recall, F1** use the threshold tuned on Validation, not 0.5.
- **ROC-AUC, PR-AUC** need no threshold. PR-AUC is the main ranking metric; a random model scores
  the positive rate.
- **Brier** checks the probabilities (lower is better; always predicting the positive rate p
  scores p(1-p)). J48 and RandomForest train on class-balanced weights, so their probabilities are
  pushed toward the minority class and their Brier is worse even when their ranking is good.
- Weka's PR area is close to, but not computed exactly like, scikit-learn's `average_precision`.

## Tuning

Each model's settings live in `Trainer.models()`. The tuner tries every setting, keeps the best
Validation PR-AUC, and never reads the holdout.

| Model | Setting that matters | Why |
|---|---|---|
| Logistic | `ridge` | Barely changes results with ~45k rows and 32 predictors |
| NaiveBayes | `discretize` | Normal vs discretized numeric predictors |
| J48 | `minNumObj`, Laplace on | Small leaves memorise noise and give 0/1 probabilities |
| RandomForest | `minLeaf` | Leaf size 1 overfits this noisy target |
| LogitBoost | `iterations` | More boosting rounds, more time |

Keep grids small (each setting is retrained). If the best setting is the last in its list, extend
the list in that direction. Run `PipelineTest` after any change.
